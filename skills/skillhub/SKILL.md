# SkillHub

Этот скил не решает задач сотрудника. Он связывает его с хабом скилов: отправляет
готовый скил ревьюеру, показывает судьбу отправки, показывает каталог и ставит
опубликованные скилы сотруднику.

Адрес хаба: https://fcba-2401-e320-c31-ff08-f0bd-fef5-9f4e-aed4.ngrok-free.app

## Настройки

Хаб отвечает только с персональным токеном сотрудника. Администратор выдаёт его
вместе с небольшим JSON, где есть `api_base_url` и `token`.

- Если рядом с этим `SKILL.md` лежит `config.json` — возьми настройки оттуда,
  ничего не спрашивая.
- Иначе ищи `~/.skillhub/config.json`, затем `skillhub.json` в рабочей папке.
- Не нашёл — попроси сотрудника вставить JSON, выданный администратором,
  и предложи сохранить его в `~/.skillhub/config.json`.
- Токен настоящий, если состоит из латиницы, цифр и подчёркиваний и начинается
  с `skh_live_`. Иначе скажи: «Плагин собран без токена, пересоберите архив» —
  и ничего не отправляй.
- Никогда не показывай токен в ответах и не записывай его в другие файлы.

Все запросы ниже идут с заголовками `Authorization: Bearer <токен>`,
`Accept: application/json` и `ngrok-skip-browser-warning: 1`.


```python
import json, pathlib, urllib.error, urllib.request

CONFIG = "path/to/config.json"    # см. «Настройки»

config = json.loads(pathlib.Path(CONFIG).read_text())
BASE = config["api_base_url"].rstrip("/")
HEADERS = {
    "Authorization": f"Bearer {config['token']}",
    "Accept": "application/json",
    "ngrok-skip-browser-warning": "1",
}

def call(method, path, body=None):
    data = json.dumps(body).encode() if body is not None else None
    request = urllib.request.Request(f"{BASE}{path}", data=data, method=method, headers={
        **HEADERS, **({"Content-Type": "application/json"} if data else {}),
    })
    try:
        with urllib.request.urlopen(request, timeout=60) as response:
            return response.status, json.loads(response.read() or b"{}")
    except urllib.error.HTTPError as e:
        return e.code, json.loads(e.read() or b"{}")
    except urllib.error.URLError as e:
        return "NETWORK", {"reason": str(e.reason)}
```


## Действие 1. Отправить свой скил

1. Возьми `SKILL.md`, созданный или изменённый в этом разговоре. Файлов несколько
   или нет ни одного — спроси, какой отправлять. Без явного выбора не отправляй.
2. Слаг — поле `name` из начала файла: строчные латинские буквы, цифры и дефисы,
   до 64 символов. Название — первый заголовок `# ` или короткое название
   от сотрудника.
3. Покажи слаг, название и первые строки, спроси подтверждение.
4. Отправь:


```python
import hashlib

content = pathlib.Path("path/to/SKILL.md").read_text(encoding="utf-8")
status, body = call("POST", "/v1/skills", {
    "slug": SLUG, "title": TITLE, "content": content, "source": "cowork",
    "idempotency_key": hashlib.sha256(f"{SLUG}\n{content}".encode()).hexdigest(),
})
print(status, body)
```


Повтор с тем же текстом безопасен: хаб вернёт прежний ответ и ничего не создаст.

Хаб маскирует ИНН, КПП, номера счетов и карт, суммы с валютой, а при пяти и более
совпадениях отклоняет скил. Видишь такие данные в тексте — предложи убрать до отправки.

## Действие 2. Узнать судьбу своей отправки

`call("GET", f"/v1/skills/{SLUG}/status")`. Ответ — состояние **своей** версии:

| `my_version.state` | Что сказать сотруднику |
| --- | --- |
| `candidate` | Скил у ревьюера, решения пока нет. |
| `current` | Скил опубликован и доступен всем. |
| `superseded` | Вышла более новая версия этого скила. |
| `rejected` | Ревьюер отклонил версию. Назови причину из `rejection_reason`. |

Ответ `404` значит, что этот сотрудник такого скила не присылал. Чужие отправки
хаб не показывает.

## Действие 3. Посмотреть каталог

`call("GET", "/v1/skills")` отдаёт `{"skills": [{"slug", "title", "version", "updated_at"}]}` —
всё, что опубликовано и доступно сотрудникам. Черновиков и чужих кандидатов там нет.

Покажи сотруднику список коротким перечнем: название, слаг и номер версии.

## Действие 4. Установить скил себе

1. `call("GET", f"/v1/skills/{SLUG}")` — вернёт `{"slug", "title", "version", "content"}`
   актуальной опубликованной версии. Ответ `404` значит, что скил ещё не выпущен.
2. Сохрани `content` как `SKILL.md` установленного скила:
   - в Claude Code — файлом `~/.claude/skills/<слаг>/SKILL.md`, он подхватится
     в новой сессии;
   - в Cowork — сохрани файл в рабочей папке и скажи сотруднику добавить его
     через «Customize → Skills», программно туда положить скил нельзя.
3. Назови сотруднику слаг и номер установленной версии.

Обновление работает так же: заново запроси скил и перезапиши файл. Номер версии
из ответа сравни с тем, что стоит у сотрудника, и скажи, что изменилось.

## Ответы хаба

| Ответ | Что сказать |
| --- | --- |
| `201`, `draft_created` | Скил отправлен. Ревьюер проверит его и выпустит в маркетплейс. |
| `proposal_created` | Правка к существующему скилу отправлена на проверку. |
| `conflict` | Правка отправлена, но скил тем временем изменили. Ревьюер разберёт её вручную. |
| `no_change` | Такой текст уже есть в хабе, отправлять нечего. |
| `skill_publishing` | Скил сейчас публикуется. Попробуйте через несколько минут. |
| `409`, `skill_archived` | Скил в архиве, правку к нему отправить нельзя. |
| `422`, `blocked` | Хаб отклонил скил: слишком много персональных данных. Уберите их и отправьте снова. |
| `422`, `invalid_title` | Хаб не принял название или слаг. Предложи исправить. |
| `422`, `missing_department` | У сотрудника в хабе не указан отдел. Обратитесь к администратору. |
| `invalid_request` | Покажи список ошибок из поля `errors`. |
| `401` | Токен недействителен или отозван. Обратитесь к администратору. |
| `403` | У токена нет нужного права. Обратитесь к администратору. |
| `413` | Скил слишком большой. |
| `429` | Слишком много запросов подряд. Подождите минуту. |
| `NETWORK` или страница вместо JSON | Не удалось достучаться до хаба. Возможно, выход в сеть к его адресу не разрешён. Передайте текст ошибки администратору. |

Не повторяй запрос сам после отказа: покажи сотруднику ответ и предложи решение.
